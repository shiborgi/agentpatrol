# AgentPatrol

Composable engineering personas, specialist profiles and shared skills. AgentPatrol
is a dependency-free JavaScript ESM library and CLI for Node.js 22+, implementing
Patrol protocol **1.0** and publishing self-contained packs that conform to the
separate **Agent Plugins 1.0.0** specification. The npm and generated plugin package
version is **1.0.0**.

AgentPatrol does not execute models, collect context, manage task state, approve
workflow gates or launch MCP servers.

## Catalog

| Persona | Eligible stages | Responsibility |
| --- | --- | --- |
| `architect` | `spec`, `plan` | Testable intent and actionable design |
| `developer` | `build` | Minimal implementation and real verification |
| `qa` | `spec-review`, `plan-review`, `build-review` | Independent evidence-based review |
| `release` | `ship` | Release readiness and operator-controlled handoff |

| Profile | Expertise |
| --- | --- |
| `general` | Repository conventions and evidence discipline |
| `react` | React boundaries, state, accessible and responsive interactions |
| `python` | Python environments, package interfaces and resource safety |
| `mcp` | MCP contract and authorization development, not server execution |
| `nextjs` | React and Next.js App Router rendering, caching and user flows |
| `service` | HTTP services; Hono and Bun workspace practices when applicable |

Personas and profiles are orthogonal. Any persona can use multiple profiles;
profile selection does not change stage eligibility or permissions. No profile
is implicitly added by `resolve`; pass `[]` for persona-only or select `general`
explicitly. Unknown IDs fail instead of falling back.

## Installation

```sh
npm install agentpatrol@1
npx agentpatrol --version
```

The installed package includes its catalog, active persona/profile sources, shared
skills, runtime, schemas and ten generated plugin packs. It has no checkout-relative
imports or dependency on sibling Patrol repositories. Source defaults always refer
to the installed package, not the caller's working directory.

## CLI

```sh
printf '%s' '{"protocolVersion":"1.0"}' | agentpatrol catalog
printf '%s' '{"protocolVersion":"1.0","persona":"developer","profiles":["react","nextjs"]}' | agentpatrol resolve
agentpatrol build --out ./portable-plugins
agentpatrol check --out ./portable-plugins
agentpatrol validate --out ./portable-plugins
agentpatrol --version
agentpatrol --help
```

`catalog` and `resolve` require one JSON object on stdin and emit one JSON object
on stdout. Diagnostics go to stderr and failures exit nonzero. Requests are closed:
unknown fields and wrong protocol versions fail. Stdin is bounded to 64 KiB and
5 seconds; serialized stdout is bounded to 1 MiB. Supported commands and options
are listed by `--help`; `--help` and `--version` are standalone commands.

All five commands accept `--root DIR` for a complete authored catalog. `build`,
`check` and `validate` also accept `--out DIR`, defaulting to `ROOT/plugins`.
Duplicate/unknown options and positional arguments fail. Use physical paths:
symlinked inputs, outputs and path ancestors are rejected.

`build` produces four persona packs with `general` plus six `profile-<id>` packs.
It writes only declared targets, preflights collisions and never deletes files or
directories. Unexpected files inside a target fail with a fresh-output suggestion;
unrelated sibling directories are ignored. Existing recognized targets can be
updated. Builds are not atomic across files; use a fresh output for deployment.
`check` compares generated bytes without writing. `validate` checks source contracts,
manifest shape, skill assets and extension integrity without requiring identical
JSON formatting. Neither command repairs drift.

## Library

```js
import {
  VERSION, PROTOCOL_VERSION, getCatalog, resolve,
  build, check, validate, validateManifest, canonicalJSON, digest,
} from 'agentpatrol';

const catalog = await getCatalog();
const agent = await resolve({
  protocolVersion: '1.0', persona: 'developer', profiles: ['react', 'nextjs'],
});
await build({ out: '/physical/path/to/portable-plugins' });
```

| Export | Signature / result |
| --- | --- |
| `VERSION`, `PROTOCOL_VERSION` | Strings `1.0.0`, `1.0` |
| `getCatalog(options?)` | Promise of the exact Patrol catalog response |
| `resolve(request, options?)` | Promise of the exact Patrol resolved response |
| `build(options?)` | Promise of `{protocolVersion,catalogVersion,plugins,out}` |
| `check(options?)`, `validate(options?)` | Promise of `{protocolVersion,catalogVersion,valid:true,plugins}` |
| `validateManifest(manifest)` | `true` or throws; closed upstream 1.0.0 manifest rules |
| `canonicalJSON(value)` | Recursively key-sorted compact JSON string |
| `digest(value)` | Lowercase SHA-256 hex of `canonicalJSON(value)` |

Options are `{root?}` for catalog/resolution and `{root?,out?}` for packaging;
paths are strings. Async exports reject on failure. `resolve` requires all three
request fields. Composition is persona instructions, sorted unique profile
instructions, then skills deduplicated in first-reference order. Skill content is
read once from the shared source. The digest covers the entire resolved response
including `catalogDigest`, except `digest`, with recursive key sorting, UTF-8 and no whitespace. Arrays retain
order. It contains no timestamps or local absolute paths.

Catalog responses require `contentDigest`: lowercase SHA-256 of all active persona
and profile descriptors and complete instruction text, plus every referenced skill
file (including reference documents and binary assets). The canonical representation
sorts object/file keys and encodes skill bytes as base64. Resolution requires
`catalogDigest`, copied from that same loaded snapshot with no separate source read.
Changes to instructions or assets invalidate both identities even with unchanged
version and IDs, preventing reuse of stale host learning. Separate invocations may
observe edits between them; compare their returned identities. See the
[fingerprint contract](docs/protocol.md) for the exact representation.

## Portable Plugins

```text
catalog.json                         # explicit active IDs, never directory discovery
agents/<id>/persona.json
agents/<id>/instructions.md
profiles/<id>/profile.json
profiles/<id>/instructions.md
skills/<id>/SKILL.md                  # one authored source per active skill
plugins/<pack>/plugin.json            # generated only
plugins/<pack>/skills/<id>/SKILL.md
plugins/<pack>/io.shiborgi.agentpatrol/metadata.json
plugins/<pack>/io.shiborgi.agentpatrol/instructions.md
```

The fixed `skills/` directory is portable. Persona/profile metadata is an
AgentPatrol extension, not a claim that the external specification defines portable
agents. Other clients may ignore the extension and still load skills. The manifest
is closed, with required `$schema` and `name`; package version is `1.0.0` and the
Agent Plugins schema URL independently targets `1.0.0`. There is no MCP launcher or
generated `mcp.json`.
Profile packs are reusable skill packs, not standalone lifecycle personas.

## Patrol Integration

`codepatrol.json` configures only portable PATH-based Patrol provider argv arrays and
verification. CodePatrol owns routing, execution adapters, workflow gates and
telemetry. ContextPatrol owns read-only context. No package imports sibling source.
An executor is intentionally omitted: installing a skills provider does not
authorize model execution, network access or deployment. Release requires separate
explicit human approval, enforced by the host rather than these instructions.

See [protocol](docs/protocol.md), [architecture](docs/architecture.md),
[contributing](CONTRIBUTING.md), [security](SECURITY.md) and [changelog](CHANGELOG.md).

## Specialist Authoring

The `nextjs-engineer` and `service-engineer` source directories express focused
stack-specialist intent. They are not catalog entries, build targets or npm package
contents. Compose `developer` (or another lifecycle persona) with the `nextjs` or
`service` profile to reuse the relevant shared stack skills while keeping lifecycle
duties and stack expertise independent. Unselected shared skills remain optional
authoring material outside the active catalog.

| Specialist source | Support skills |
| --- | --- |
| `nextjs-engineer` | test-first, minimal-implementation, preserve-access-paths, frontend-a11y-check, design-token-discipline, nextjs-app-router, name-interaction-evidence, root-cause-first, evidence-based-completion, answer-by-prototype, write-observable-interaction, detect-interaction-drift |
| `service-engineer` | test-first, minimal-implementation, preserve-access-paths, hono-service, bun-workspace, root-cause-first, evidence-based-completion, answer-by-prototype |

## Development

```sh
npm ci
npm run build          # only after intentional source changes
npm run verify         # drift first, validation second, isolated tests last
npm run release-check  # drift first, then offline installed-package smoke
```

No verification test rewrites repository artifacts, and there is no automatic
prepack build to hide stale generated output.
